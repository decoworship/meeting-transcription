# Ata — Update de projeto com cliente

A mais formal dos tipos. Presuma que o cliente vai ler, e possivelmente encaminhar internamente. A ata funciona como registro compartilhado do combinado — é o instrumento que evita a conversa "mas vocês não tinham dito que...".

## Estrutura

```markdown
# Ata — [Projeto] · Update [período ou data]

**Data:** ... · **Participantes:** [agrupados por organização]

## Resumo
[3-5 linhas. O que avançou, o que travou, o que precisa de decisão.]

## Status por frente

### [Frente / módulo / entregável]
**Situação:** [em andamento / concluído / bloqueado]
[O que foi reportado, com números quando citados.]

## Decisões

## Pendências

### Do nosso lado
- [ ] Ação — **Responsável** — prazo

### Do lado do cliente
- [ ] Ação — **Nome (Organização)** — prazo

## Pontos em aberto

## Riscos e alertas

## Próxima reunião
```

## Notas específicas

**Separar pendências por lado é a razão de existir desta ata.** Um item que depende do cliente misturado na lista geral desaparece. Separado, ele é cobrável na próxima reunião. Se um item depende de ambos, coloque no lado de quem precisa agir primeiro e explicite a dependência.

**Status por frente** deve espelhar como o projeto é organizado — por módulo, por região, por praça, pelo que a reunião usou. Não invente uma taxonomia nova. Se a reunião cobriu várias operações ou localidades distintas, uma subseção para cada.

**Riscos** entram quando alguém sinalizou preocupação com prazo, dado, capacidade ou dependência externa. Se ninguém levantou risco, omita a seção — seção vazia treina o leitor a ignorar.

**Tom neutro.** Discordância interna do time não vai para a ata de cliente. Se o time divergiu e depois fechou uma posição, registre só a posição fechada. Se a divergência é com o cliente, registre ambas as posições de forma factual, sem adjetivos.

**Compromissos verbais são o item mais importante a capturar.** "Vamos ver isso até sexta", "eu te mando os dados amanhã" — parecem casuais na fala e são exatamente o que a ata precisa fixar, com nome e data.
